# 数据知识产权协商估值引擎 v1.3 / v1.4 系数拆分技术方案

**项目：** `guolliu1033/data-ip-valuation-engine`  
**版本建议：** v1.3（加工难度）与 v1.4（应用场景）  
**编制日期：** 2026-08-22  
**编制人：** Manus AI

---

## 摘要

本方案在不改变德阳成本法 L1 结构的前提下，将现有的加工难度系数 `b` 与应用场景价值系数 `c` 由单一粗分档升级为**可编程、多维、可解释、可审计**的 L2 推荐模型。L1 仍为：

```text
A = a + (d + e) × b + a × c
```

其中，`a` 为审定直接投入成本，`d+e` 为加工必要成本，`b` 为加工难度系数，`c` 为应用场景附加价值系数。该结构与当前开源项目保持一致；当前项目也已将 L2 定位为系数自动推荐、L3 定位为与收益法的交叉验证。[5] [6]

推荐 v1.3 采用五个子系数：**流程拓扑、业务规则、质量治理、多源异构整合、安全合规与受控交付**。推荐 v1.4 采用五个子系数：**已验证需求、稀缺与不可替代性、有效覆盖与可行动价值密度、场景复用与商业化范围、价值实现确定性**。两个系数均使用有界加权平均、统一四档尺度 `{1.0, 1.7, 2.7, 4.0}` 与一位小数展示，既可复现当前低/中/高或好/很好/特好的分档，又不会改变 L1 的量纲与结构。

> **定位声明。** 本引擎输出的是数据知识产权交易、许可、使用、入股或质押前的**协商估值参考与参数建议**，而非当然替代依法应由资产评估专业人员出具的法定资产评估报告。德阳公开研讨资料亦将协商估值定位为服务交易、使用、入股、质押等主体的参考。[7]

| 决策 | 推荐方案 | 关键原因 |
|---|---|---|
| b 的合成方式 | 成本敏感权重的有界加权平均 | 延续现有“流程数+判定条件数”逻辑，避免乘法放大不确定项。 |
| c 的合成方式 | 场景商业化权重的有界加权平均，先过合规/权利闸门 | 将需求、稀缺、价值密度作为主要价值驱动；不以高稀缺抵消不可流通风险。 |
| AI 的角色 | **AI 抽取 + 规则裁决** | AI 处理非结构化描述，最终分数由确定性规则重算，便于审计与离线降级。 |
| 人工协商 | 保留但留痕 | 允许协商，不允许无依据跳档；超推荐阈值须附理由、证据与审批。 |
| 可比案例 | 作为 c 的解释和异常校验，不直接回归系数 | 数据交易金额高度依赖权利范围、期限、交付方式与采购结构，不能简单均价化。 |

## 1. 依据、边界与兼容原则

### 1.1 规范与理论映射

GB/T 46353—2025 已由国家标准全文公开系统列为现行标准；其名称为《信息技术 大数据 数据资产价值评估》。[1] GB/T 36344—2018《信息技术 数据质量评价指标》亦为现行标准。[2] 中评协《资产评估专家指引第 9 号——数据资产评估》将数据获取、存储、加工、挖掘、保护、共享列为技术因素，并在成本法中提出以数据效用修正成本的思路；其数据效用讨论涵盖质量、流通、垄断和价值实现风险，并在市场法中讨论技术、价值密度、期日、容量及其他修正因素。[3] [4]

| 本方案对象 | 直接理论依据 | 引擎中的实现边界 |
|---|---|---|
| `B1`、`B2` | 中评协指引中的数据导入预处理、统计分析、数据挖掘和技术因素 | 计量为可审计的步骤与原子判定数量，不用“难/不难”的主观词。 |
| `B3` | GB/T 36344 的规范性、完整性、准确性、一致性、时效性、可访问性质量框架；中评协质量约束规则思想 | 仅计算为达到约定质量要求所增加的治理工作量，不把质量结果本身重复当作价值。 |
| `B4`、`B5` | 数据多样性、获取/存储/加工/保护/共享技术因素及隐私风险 | 用源系统数、格式类别和受控交付措施数度量增量复杂度。 |
| `C1`、`C4` | 应用要素中的使用范围、应用场景、商业模式和供求关系 | 用付费客户、合格商机、场景数、交付方式及权利范围量化。 |
| `C2` | 供求、数据垄断或不可替代性逻辑 | 用可合法替代供应方数量和可复现难度证据量化。 |
| `C3` | 市场法中“有效数据占总体数据比例”的价值密度思想 | 用目标覆盖率与可行动记录比例的较低者量化。 |
| `C5` | 数据管理、流通、增值开发、安全等价值实现风险 | 采用风险反向评分，并设置合规与权利清晰度硬闸门。 |

### 1.2 与当前开源项目的衔接

当前 `index.html` 的 L2 将 `b` 依据运算流程数和判定条件数分为低、中、高难度，并将 `c` 依据“好/很好/特好”分三档；其现有 b 区间为低档 `(0.1, 1.5]`、中档 `(1.5, 3]`、高档 `(3, 10]`，c 区间为好 `(0.1, 2]`、很好 `(2, 5]`、特好 `(5, 15]`。[6]

本方案只替换 L2 的**推荐逻辑**。L1 公式、成本口径、滑块协商空间与 L3 收益法偏差告警均保持不变。

```text
输入材料 / 表单 / AI 抽取
          ↓
v1.3 scoreB() / v1.4 gateC()+scoreC()    ← 新增 L2
          ↓
推荐 b、c + 推荐区间 + 证据摘要
          ↓
双方协商确认或人工覆写（留痕）
          ↓
A = a + (d+e)×b + a×c                  ← 原 L1 不变
          ↓
与收益法对比、偏差阈值告警              ← 原 L3 不变
```

| 兼容规则 | 实现要求 |
|---|---|
| 参数不改名 | 保持 `a`、`d`、`e`、`b`、`c` 与既有计算接口一致。 |
| b/c 仍为无量纲系数 | 不将质量分、市场规模或案例交易额直接塞入 L1。 |
| 现有区间不改变 | 新规则输出用于默认值、推荐区间与档位标签；用户仍可在原区间内协商。 |
| 高值控制 | 自动推荐常规范围限制为 `1.0–4.0`；`b>4.0` 或 `c>4.0` 只能人工协商覆写，并需证据。 |
| 覆写审计 | 与推荐值相差超过 `0.5` 或跨原有档位时，必须记录原因、证据 ID、审批人和日期。 |

## 2. 共用计算约定

### 2.1 统一尺度、加权与舍入

每个子系数均取以下四档：

| 子系数档位 | 数值 | 语义 |
|---|---:|---|
| 基础 | 1.0 | 基础、单一或低工作量/低场景扩展条件。 |
| 一般 | 1.7 | 存在可验证的增量复杂度或单一明确商业化条件。 |
| 较高 | 2.7 | 多项可验证要素同时存在，且对成本或场景价值有实质影响。 |
| 高 | 4.0 | 高度复杂或高价值条件同时满足，并有可审计证据。 |

统一舍入函数为：

```text
roundHalfUp(x, 1) = floor(10 × x + 0.5) / 10
clamp(x, min, max) = max(min, min(x, max))
```

加权平均优于未归一化求和，因为权重之和为 1，输出可保留原 b/c 的量纲。加权平均也优于乘法合成，因为任何一个不完整或误判字段都不会被乘法无限放大或压缩；在协商估值中，稳定、可解释与可覆写比理论上的极端敏感性更重要。

### 2.2 数据质量与风险的防重复计量

`a`、`d`、`e` 反映已审定的成本；b 反映将这些必要成本转化为约定交付物时的**相对复杂度**；c 反映已形成数据知识产权在明确场景中的**附加价值**。因此：

| 禁止做法 | 正确做法 |
|---|---|
| 因“准确率高”直接提高 b | 仅在实现该准确率需要新增规则、校验、治理或交付控制时，提高 `B3`。 |
| 因“数据很稀缺”直接忽略合法来源或权利问题 | c 先过 `C5` 闸门；闸门失败时阻断，不评分。 |
| 把可比交易金额除以数据量后直接当作 c | 用案例说明需求、稀缺、交付与权利范围；金额只作协商旁证。 |
| 把授信额、融资额或累计成交额当作单笔交易价 | 按金额口径分层展示；只有合同/成交口径可作为价格旁证。 |

# 第一部分：v1.3 加工难度系数 b

## 3. b 的子系数、输入字段与分档规则

### 3.1 输入字段契约

| 字段 | 类型 | 可编程定义 |
|---|---:|---|
| `process_step_count` | `int` | 在读取、清洗、标准化、匹配/关联、转换/特征、分析/建模、验证、发布中，计数实际执行且可独立验收的原子处理步骤；同一步骤重复运行不重复计数。 |
| `business_rule_count` | `int` | 影响数据保留、归类、匹配、计算或输出的原子业务判定数；`A AND B` 计为 2 个原子条件；质量校验规则不计入本字段。 |
| `quality_dimension_count` | `int 0..6` | 在六个质量维度中，有书面阈值、检测规则和结果记录的维度数。 |
| `quality_check_count` | `int` | 已实际执行的质量检查规则数，例如非空、值域、格式、主键、跨表一致性、时效阈值。 |
| `source_system_count` | `int` | 独立系统、数据库、API 或外部文件主体数；同一系统多张表计 1。 |
| `data_format_type_count` | `int 0..6` | 实际处理的格式类别数：结构化表、半结构化 JSON/XML、文本、图像、音视频、时序/流式数据各计 1。 |
| `special_control_count` | `int 0..6` | 已实施控制类别数：脱敏/去标识、敏感字段识别与掩码、细粒度授权、用途/期限控制、血缘与审计、隐私计算/可信空间。 |
| `has_privacy_computing_or_trusted_space` | `bool` | 是否使用隐私计算、数据沙箱、可信数据空间或等效的“数据不出域”控制。 |

### 3.2 五个 b 子系数

| 代码 | 子系数 | 数据资产评估理论依据 | 直接影响 |
|---|---|---|---|
| `B1` | 流程拓扑复杂度 | 中评协将导入预处理、统计分析、数据挖掘列为数据资产研发流程，并将加工、挖掘列为技术因素。[3] | 加工链路长度和验收节点增加。 |
| `B2` | 业务规则与判定复杂度 | 当前项目已有“判定条件数”输入；该项保留并细化为原子规则。 | 决策逻辑、测试用例和维护负荷增加。 |
| `B3` | 质量治理负荷 | GB/T 36344 提供六维数据质量框架；中评协指引要求用规则模块对质量进行检测和汇总。[2] [3] | 为达到约定质量阈值的检查、修复和留痕工作增加。 |
| `B4` | 多源异构整合复杂度 | 数据资产具有多样性；技术因素涵盖获取、存储、加工等环节。[3] | 源端协调、字段映射、主数据对齐与格式转换工作增加。 |
| `B5` | 安全合规与受控交付负荷 | 中评协将数据保护、共享列为技术因素并提示隐私风险；国标价值影响要素亦强调安全合规。[1] [3] | 为可控交付新增脱敏、授权、审计或受控计算工作。 |

### 3.3 可直接实现的分档表

| 代码 | 基础：1.0 | 一般：1.7 | 较高：2.7 | 高：4.0 | 规则合并方法 |
|---|---|---|---|---|---|
| `B1` | `process_step_count <= 2` | `3..4` | `5..6` | `>= 7` | 单字段查表。 |
| `B2` | `business_rule_count <= 3` | `4..6` | `7..12` | `>= 13` | 单字段查表。 |
| `B3` 质量治理 | `dimension<=1 AND check<=5` | `dimension 2..3 OR check 6..20` | `dimension 4..5 OR check 21..50` | `dimension==6 AND check>50` | 分别计算 `dimensionScore` 与 `checkScore`，取 `max`。 |
| `B4` 多源整合 | `source<=1 AND format==1` | `source==2 OR format==2` | `source 3..4 OR format==3` | `source>=5 OR format>=4` | 分别计算 `sourceScore` 与 `formatScore`，取 `max`。 |
| `B5` 受控交付 | `control==0` | `control==1` | `control 2..3` | `control>=4 OR trusted_space==true` | `trusted_space==true` 直接取 4.0；否则按控制数查表。 |

为避免二义性，`B3` 与 `B4` 使用下列伪代码；其余维度可直接按表分档：

```text
B3 = max(bucketQualityDimension(quality_dimension_count),
         bucketQualityCheck(quality_check_count))

B4 = max(bucketSourceSystem(source_system_count),
         bucketDataFormat(data_format_type_count))
```

## 4. b 的权重、公式与 L2 映射

### 4.1 两套权重方案

| 方案 | B1 | B2 | B3 | B4 | B5 | 适用条件 | 评价 |
|---|---:|---:|---:|---:|---:|---|---|
| `W0` 等权基准 | 0.20 | 0.20 | 0.20 | 0.20 | 0.20 | 冷启动、无本地标注样本或需降低专家先验影响 | 稳健，但弱化现有流程/判定条件的连续性。 |
| `W1` 成本敏感专家权重（**推荐**） | 0.30 | 0.25 | 0.20 | 0.15 | 0.10 | 当前项目 v1.3 默认 | 流程和业务规则最直接影响加工必要成本；质量、整合、合规体现边际工作量。 |

### 4.2 推荐合成公式

```text
b_raw = 0.30×B1 + 0.25×B2 + 0.20×B3 + 0.15×B4 + 0.10×B5
b_recommended = clamp(roundHalfUp(b_raw, 1), 0.1, 10.0)
```

L2 档位映射保持项目原有区间：

```text
b_recommended <= 1.5  → 低难度
1.5 < b_recommended <= 3.0 → 中难度
b_recommended > 3.0   → 高难度
```

自动推荐默认只输出 `1.0–4.0`。原高难度区间 `(3,10]` 仍保留给有充分依据的协商结果；大于 4.0 的值必须填写 `override_reason`、证据编号和审批人。

### 4.3 b 的实现接口

# 第二部分：v1.4 应用场景价值系数 c

## 5. c 的子系数、输入字段与硬闸门

### 5.1 输入字段契约

| 字段 | 类型 | 可编程定义 |
|---|---:|---|
| `signed_paying_customer_count` | `int` | 评估基准日前 12 个月内，已签约并发生或约定付费的独立客户数；同一集团计 1。 |
| `qualified_pipeline_count` | `int` | 有需求说明、预算或采购计划、预计 12 个月内实施且由业务负责人确认的商机数；口头意向不计。 |
| `authorized_competing_supplier_count` | `int|null` | 能合法提供同等核心字段、相近时效和同等使用权范围产品的独立供应方数；未知必须为 `null`，不能填 0。 |
| `exclusive_or_hard_to_replicate` | `bool` | 存在排他/独家合法授权，或等价复现需要重新连续采集满 12 个月以上且无公开替代。 |
| `coverage_share_pct` | `number 0..100` | 有效覆盖的对象、地域、机构或时间窗口 ÷ 目标使用范围。 |
| `actionable_record_ratio_pct` | `number 0..100` | 满足目标场景最小字段集、质量和时效要求且可直接使用的记录 ÷ 总记录。 |
| `use_case_count` | `int` | 已落地或有已签需求规格书的独立业务场景数；同一场景不同客户不重复计数。 |
| `delivery_mode_count` | `int 0..5` | 经测试可交付的模式数：API、批量包、数据报告/指数、受控查询/沙箱、隐私计算/可信空间。 |
| `right_scope_score` | `int 0..3` | `0` 仅内部；`1` 单客户且不可再许可；`2` 多客户、单行业或区域非排他；`3` 跨行业/区域多客户，许可边界清晰。 |
| `legal_compliance_status` | `enum` | `pass`、`conditional`、`fail`、`unknown`。 |
| `security_level` | `enum` | `basic`、`controlled`、`high_control`。 |
| `right_clarity_status` | `enum` | `clear`、`conditional`、`unclear`。 |
| `operating_months` | `int` | 在目标场景连续稳定交付并留存服务记录的月数。 |
| `sla_attainment_pct` | `number 0..100` | 最近 6 个月或完整运营期达到合同/说明中 SLA 的月份比例。 |

### 5.2 先执行 C5 的不可绕过闸门

```text
if legal_compliance_status in {"fail", "unknown"}
   or right_clarity_status == "unclear":
    return BLOCK
```

`BLOCK` 时引擎不得输出 c 的单点推荐，也不得因数据稀缺或需求强劲而人工绕过。应输出整改清单，例如来源授权、个人信息处理基础、敏感/重要数据判断、合同使用权、跨境要求、数据处理者责任、审计记录或安全控制证明。

### 5.3 五个 c 子系数

| 代码 | 子系数 | 理论依据 | 价值解释 |
|---|---|---|---|
| `C1` | 已验证需求与市场规模 | 应用要素包含使用范围、应用场景、商业模式和供求关系；经济因素包括市场规模、市场应用与竞争。[1] [3] | 可验证买方需求比主观“前景好”更可靠。 |
| `C2` | 稀缺性与不可替代性 | 数据垄断/行业地域占比、供求与其他修正因素。[3] | 竞争供应方少、合法复现困难或独家授权会提高协商地位。 |
| `C3` | 有效覆盖与可行动价值密度 | 中评协市场法将有效数据占总体数据比例作为价值密度的逻辑。[3] | 大而无效或精而覆盖窄均不能给高分。 |
| `C4` | 场景复用与商业化范围 | 相同数据因应用领域、使用方法、获利方式不同而价值不同。[3] | 可在更多场景、以更多安全交付方式、在更清晰许可范围下复用，价值实现空间更大。 |
| `C5` | 价值实现确定性 | 数据管理、流通、增值开发和安全风险影响价值实现。[3] | 合规、权利清晰、受控交付和稳定运营将风险反向降低。 |

### 5.4 可直接实现的分档表

| 代码 | 基础：1.0 | 一般：1.7 | 较高：2.7 | 高：4.0 | 规则合并方法 |
|---|---|---|---|---|---|
| `C1` 需求 | `signed==0 AND pipeline<=1` | `signed==1 OR pipeline 2..3` | `signed 2..5 OR pipeline 4..10` | `signed>=6 OR pipeline>=11` | 取签约客户分与合格商机分的 `max`。 |
| `C2` 稀缺 | `supplier>=5 AND exclusive==false` | `supplier 3..4` | `supplier 1..2 OR exclusive==true` | `supplier==0 AND exclusive==true` | `supplier==null` 时仅能输出区间或待核验，不输出单点。 |
| `C3` 覆盖/价值密度 | `coverage<30` 或 `actionable<60` | `coverage 30..59` 且 `actionable 60..74` | `coverage 60..84` 且 `actionable 75..89` | `coverage>=85` 且 `actionable>=90` | 分别按 coverage 与 actionable 查表，取 `min`。 |
| `C4` 复用/商业化 | 场景≤1、交付≤1 或权利≤1 | 场景=2、交付=2 或权利=2 | 场景 3..4、交付=3 或多客户清晰权利 | 场景≥5、交付≥4 且跨行业/区域多客户许可清晰 | 分别给场景、交付、权利评分，取 `min`；保证高档必须全面成立。 |
| `C5` 确定性 | `conditional`、`basic`、运营<3 月、SLA<80% 或权利条件性 | `controlled`、运营 3..5 月、SLA 80..89% | `controlled`、运营 6..11 月、SLA 90..94% | `pass`、权利清晰、`high_control`、运营≥12 月且 SLA≥95% | 闸门通过后，按法律、权利、安全、运营、SLA 五项分别分档，取 `min`。 |

`C4` 的权利评分应使用如下固定映射：

```text
right_scope_score 0..1 → 1.0
right_scope_score 2    → 1.7
right_scope_score 3 且许可允许跨行业/区域多客户 → 4.0
right_scope_score 3 但范围未被合同明确 → 2.7
```

## 6. c 的权重、公式与可比案例使用规则

### 6.1 两套权重方案

| 方案 | C1 | C2 | C3 | C4 | C5 | 使用条件 | 评价 |
|---|---:|---:|---:|---:|---:|---|---|
| `W0` 等权基准 | 0.20 | 0.20 | 0.20 | 0.20 | 0.20 | 新产品、公共数据授权运营初期或样本稀缺 | 相对中性。 |
| `W1` 场景商业化专家权重（**推荐**） | 0.30 | 0.25 | 0.20 | 0.15 | 0.10 | 当前 v1.4 默认 | 需求、稀缺和价值密度合计 75%，体现国标供求/价值密度逻辑；C5 主要通过闸门控制。 |

### 6.2 推荐公式

```text
if gateC(inputs) == BLOCK:
    c_recommended = null
else:
    c_raw = 0.30×C1 + 0.25×C2 + 0.20×C3 + 0.15×C4 + 0.10×C5
    c_recommended = clamp(roundHalfUp(c_raw, 1), 0.1, 15.0)
```

档位映射与现有页面保持一致：

```text
c_recommended <= 2.0 → 好
2.0 < c_recommended <= 5.0 → 很好
c_recommended > 5.0 → 特好
```

任何 `c>4.0` 的人工协商结果，必须附 `case_id`、权利类型、期限、交付方式、地域与使用范围、修正原因。`c` 的高值不是对收入的预测，仍须经过 L3 收益法、市场法或交易谈判的交叉验证。

### 6.3 可比案例库：使用方式

可比案例用于解释 `C1–C5` 的相对位置、为协商区间提供旁证，以及发现显著异常。它不直接用交易金额回归 c。建议保存如下字段：

```text
case_id, source_url, disclosure_date, product_name, amount, amount_type,
right_type, term, industry, data_type, delivery_mode, use_case,
customer_count, scarcity_evidence, quality_coverage_evidence,
compliance_evidence, price_disclosure_level, review_status
```

相似度可按以下确定性公式计算：

```text
similarity = 0.30×industry_match
           + 0.25×data_type_match
           + 0.20×scenario_match
           + 0.15×right_scope_match
           + 0.10×delivery_match
```

每一项只能是 `0`、`0.5` 或 `1`。仅 `similarity>=0.70` 且金额口径为 `exact`（单笔成交/合同）或 `aggregate`（多笔/多产品合计）的案例可显示为金额旁证。`aggregate` 不得除以笔数推成单笔均价；`finance_only`、`range` 与 `unverified_user_input` 不参与自动金额比较。

# 第三部分：AI 评估路径

## 8. 共同设计：AI 抽取，不替代规则

AI 的适当角色是把描述文本、报告摘要、合同摘要和已审核案例转化为结构化字段；最终 b/c 必须由与离线模式完全相同的规则函数计算。页面中的“推理链”应命名为**可审计评分依据摘要**，只展示“字段 → 证据 → 规则档位 → 权重贡献 → 缺口”，而不要求、展示或保存模型的隐藏思维过程。

| 必存审计字段 | 目的 |
|---|---|
| `assessment_id`、`engine_version`、`rule_version`、`weight_scheme` | 版本化与可复算。 |
| `model_id`、`prompt_template_version`、`prompt_hash`、`input_hash` | AI 调用可追溯。 |
| `evidence_id`、`excerpt`、`source_type` | 每个抽取字段均有来源。 |
| `ai_structured_output`、`schema_valid`、`rule_recalculation` | 区分 AI 提取与规则决策。 |
| `override_reason`、`approver`、`approved_at` | 协商覆写可审计。 |
| `redaction_status`、`retention_policy` | 个人信息、医疗数据与商业秘密最小化处理。 |

## 12. L1 复算

| 参数 | 数值 |
|---|---:|
| `a` | 26.0 |

| `b` | 1.4 |
| `c` | 1.4 |

```text
(d+e) = 20 + 6 = 26
(d+e)×b = 26×1.4 = 36.4
```

| C4 | 单一场景、基础商业化范围 | 1.0 | 0.15 | 0.150 |
| C5 | 仅达到最低可流通确定性 | 1.0 | 0.10 | 0.100 |
| **合计** |  |  |  | **1.385** |

`roundHalfUp(1.385, 1) = 1.4`，故在上述条件成立时可复现 c=1.4。

| 结论 | 结果 |
|---|---|
| b 是否可复现 | 可以，在条件性反向配置下从 1.385 舍入为 1.4。 |
| c 是否可复现 | 可以，在条件性反向配置下从 1.385 舍入为 1.4。 |
| 事实核验状态 | 待补加工说明、规则清单、质量报告、数据源清单、合同权利边界、需求/客户证据、合规意见及运营记录。 |
| 建议可接受差异 | 正式复算中，建议将单一系数差异控制为 `±0.1`；同时以 L3 收益法偏差不超过 15% 作为第二道一致性校验。 |

差异若出现，应解释为新增事实证据引起的评分变化，而不应为了机械复现 1.4 而压低或抬高真实评分。对于医疗数据，还应将个人信息、敏感个人信息、数据来源、授权路径、使用目的及安全交付措施作为 C5 闸门的优先核验材料。

## 16. 限制与使用说明

本方案以公开标准、专家指引、公开交易/资产化案例和用户提供的案例输入为基础。公开市场中相当多的交易仅披露累计金额、融资授信、产品挂牌或多笔合计，未披露可比所必需的权利范围、许可期限、交付量、采购单位与单笔合同价。因此案例库必须保留金额口径与资料限制，不能将非成交价伪装为成交价。

本方案建议在上线后三个月内收集不少于 30 个经双方确认、字段完整且有 L3 结果的数据样本，再比较 `W0` 与 `W1` 对收益法偏差、人工覆写率和协商周期的影响。若本地样本显示某一子系数持续偏高或偏低，再以版本化方式调整权重；不得静默改写历史估值结果。

> **评估基础披露。** 本文的系数为协商估值引擎中的 L2 推荐参数；c 不是收益预测，公开案例金额不是单价模型。案例资料的截至日为 2026-08-22；用户提供的医疗案例未找到可独立核验的公开原始资料。本文是技术研究与实现方案，不构成针对任何主体的资产评估结论、法律意见或投资建议。
